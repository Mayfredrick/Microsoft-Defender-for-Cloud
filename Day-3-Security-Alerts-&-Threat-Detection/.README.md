## Security Alerts

A security alert is a warning that potentially malicious or suspicious activity has been detected on an organization's resources.

Security alerts can provide important information that helps an administrator understand what may have happened and determine what needs to be investigated.

Some of the information available in an alert includes:

 Severity
 Alert name
 Affected resources
 Resource group
 Activity start time
 Last update time
 MITRE ATT&CK tactics
 Alert status

## Security Recommendation vs Security Alert

One important concept I learned during this lab was the difference between a security recommendation and a security alert.

Security Recommendation:
Provides guidance about security weaknesses or configuration issues and recommends actions that can improve the security of a resource.

Security Alert:
Warns that potentially suspicious or malicious activity has been detected or may be occurring.

A simple way I understand the difference is:

 Recommendation = something that should be improved.
 Alert = potentially suspicious activity has been detected.


## Understanding Alert Severity

Severity is important because it helps an administrator understand the potential impact of an alert.

If multiple alerts are present, severity can help the administrator prioritize which alerts should receive attention first. However, the alert should still be investigated to understand the actual situation before deciding what action to take.


## Identifying Affected Resources

Identifying the affected resource is important during an investigation because it helps determine where the suspicious activity was detected.

The administrator can use the affected resource and resource group information to investigate the activity and determine whether other resources may also have been affected.

## Importance of Date and Time

The activity start time and last update time can help establish a timeline during an investigation.

A timeline can help an administrator correlate the alert with other events and activities that occurred around the same time. This can provide additional information about what happened and how the incident developed.

## Investigating Before Taking Action

I learned that an administrator should investigate an alert and gather more information before immediately making changes.

Investigation can help determine:

 What happened
 When the activity occurred
 Which resource was affected
 How serious the activity may be
 Whether additional resources may have been affected
 What action should be taken

Taking action without understanding the situation could potentially cause additional problems or make an investigation more difficult.
